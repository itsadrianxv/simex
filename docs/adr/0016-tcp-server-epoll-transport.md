# Epoll-based TCPServer transport for the order gateway

The TCP order gateway previously ran a `poll()` loop with short timeouts (10 ms while accepting, 2 ms in the data phase) on a single accepted connection, using the `stopping_` flag as its only shutdown signal. The in-process `OrderServer` seam already anticipated a real transport ("TCP/epoll transport can be attached later"), and the reference implementation in `Building Low-Latency Applications with C++` (Chapter 12) factors its networking into a reusable `TCPServer` plus `TCPSocket` pair. Adopting that shape gives the gateway a genuine epoll event loop while keeping protocol semantics in one place.

The gateway now delegates its event loop to a new generic `simex::transport::TCPServer` engine, with per-connection `TCPSocket` buffers, and keeps its own responsibilities on top: fixed-size frame reassembly with sequence validation, single-session admission (further connections are accepted and closed immediately), the five-second response watchdog, and `TcpOrderGateway`'s public API — so `ExchangeService` is unchanged. The engine registers sockets with `EPOLLIN | EPOLLET` only (edge-triggered), which imposes two disciplines the code follows explicitly: reads drain to `EAGAIN` inside one round (including the listener's accept loop), and outbound bytes are flushed opportunistically each round with the unsent tail retained — deliberately not registering `EPOLLOUT`, and fixing the reference book's bug of discarding partially sent buffers. `stop()` writes a gateway-owned `eventfd` registered through the engine's generic `registerExternalFd`, so shutdown wakes `epoll_wait` immediately instead of waiting out the poll timeout; the 10 ms timeout remains as the watchdog tick. `poll(timeout_ms)` is parameterized, keeping the book's zero-timeout busy-spin available but unused (left as a TODO).

**Status:** accepted

**Consequences:** The engine deviates from the book where the book is sloppy: `epoll_create1(EPOLL_CLOEXEC)` and `accept4(..., SOCK_NONBLOCK | SOCK_CLOEXEC)` replace the older calls, accepted sockets get `TCP_NODELAY`, per-connection buffers are 64 KiB instead of 64 MiB (TODO to revisit), disconnected sockets are actually freed, and there is no `Logger` dependency. The `recv` callback keeps the book's `(TCPSocket*, Nanos rx_time)` signature but passes user-space time; the wire protocol does not change and `rx_time` is still stamped by the runtime. `TcpOrderGateway` semantics are preserved (peer close still maps to `sessionEnded`, protocol errors still fail health, shutdown stays prompt), and the epoll story is now backed by tests: a dedicated `TCPServer` check (two simultaneous connections, fragmented echo, eventfd wakeups, rejected extra connections, abrupt-close reaping) and a new exchange-service regression covering a participant that closes its socket mid-session.
